# Go backend despite a TypeScript (Next.js) frontend

We're using Go for the backend even though the frontend is Next.js/TypeScript, rather than a single-language Node/Express stack. This isn't a technical requirement of the Velocity Tracker domain — the team already builds backends in Go and has existing familiarity and conventions there, so reusing that expertise outweighs the convenience of one language end-to-end for a small internal tool.
